Part 1: Understanding Data Visualization

Principles of Good Visualization

Before we dive into code, let’s establish some fundamental principles. Good visualizations should:

1. Be Clear and Informative

Every element should help the reader understand your data. This means:
- Proper axis labels with units
- Clear titles that explain what’s being shown
- Legends when multiple groups are displayed
- Unambiguous visual elements

2. Accurately Represent Data

The visual representation must match the underlying data:
- ❌ Don’t use 3D effects that distort perception
- ❌ Don’t truncate bar chart axes (they must start at zero)
- ✅ Do use appropriate scales
- ✅ Do maintain proportional relationships

3. Match Dimensions

The number of visual dimensions should match the data dimensions:
- 1 variable → 1-dimensional plot (bar chart, histogram)
- 2 variables → 2-dimensional plot (scatter plot, line graph)
- 3+ variables → use color, size, facets (not 3D!)

4. Use Appropriate Visual Encodings

Different data types need different encodings:

Data Type Good Encoding Poor Encoding
Categorical Color, shape, position Line (implies continuity)
Continuous Position, size, color gradient Discrete shapes
Ordered Sequential colors Random colors
Time series Line, position along x-axis Unordered categories

5. Be Intuitive

Your audience should understand the visualization without extensive explanation:
- Follow conventions (time flows left to right)
- Use familiar chart types when possible
- Avoid misleading visual tricks
- Include reference lines when helpful

Common Visualization Mistakes to Avoid

The “Lying with Statistics” Hall of Shame:
1. Truncated axes on bar charts (makes differences look bigger)
2. Cherry-picked scales that hide or exaggerate trends
3. 3D charts that make values impossible to compare
4. Dual y-axes that can be manipulated to show false correlations
5. Too many colors that confuse rather than clarify
6. Pie charts with many slices (almost always use a bar chart instead!)

Part 2: The Three Frameworks

R offers three main approaches to creating visualizations. Understanding their philosophies helps you choose the right tool.

Base R: The Painter’s Canvas

Philosophy: Build plots like painting on a canvas—add elements one at a time.

Pros:
- No additional packages needed
- Fine-grained control
- Good for quick, simple plots

Cons:
- Verbose code for complex plots
- Harder to maintain consistency
- Limited automatic features (like legends)

When to use: Quick exploratory plots, very simple visualizations

Code 
# Base R example (don't run - just for illustration)  
plot(pdat$Date, pdat$Prepositions)  
points(pdat$Date[pdat$Region == "North"],   
       pdat$Prepositions[pdat$Region == "North"],   
       col = "red")  
legend("topleft", legend = c("North", "South"),   
       col = c("red", "black"), pch = 1)

Lattice: The Template Approach

Philosophy: Use pre-designed templates that are easy to invoke but hard to customize.

Pros:
- Excellent for multi-panel plots
- Very concise code
- Good default aesthetics

Cons:
- Difficult to customize
- Less flexible than ggplot
- Smaller user community

When to use: Quick multi-panel comparisons, academic work with simple plots

Code 
# Lattice example (don't run - just for illustration)  
library(lattice)  
xyplot(Prepositions ~ Date | GenreRedux, data = pdat)

ggplot2: The Grammar of Graphics

Philosophy: Build plots like sentences—combine grammatical elements (data, aesthetics, geometries, scales).

Pros:
- Extremely flexible
- Consistent, logical syntax
- Beautiful defaults
- Massive ecosystem of extensions
- Active community

Cons:
- Requires learning the “grammar”
- Can be verbose for very simple plots
- Requires installing tidyverse

When to use: Almost everything! Especially publication-quality figures and complex visualizations.

Why We Focus on ggplot2

This tutorial focuses exclusively on ggplot2 because:

  1. It’s become the industry standard in R
  2. The grammar approach is powerful and transferable
  3. Customization is straightforward once you understand the system
  4. It produces publication-ready graphics
  5. Extensive documentation and community support

The “grammar of graphics” was developed by Leland Wilkinson and implemented in R by Hadley Wickham. It treats visualizations as composed of layers that can be combined systematically.

The ggplot2 Philosophy: Building in Layers

Think of a ggplot as a layered cake where each layer adds information:

The Building Blocks:

  1. Data - What you’re visualizing
  2. Aesthetics (aes) - What goes where (x, y, color, size, etc.)
  3. Geometries (geom_*) - How to display it (points, lines, bars)
  4. Scales (scale_*) - How aesthetics map to values
  5. Themes (theme_*) - Non-data visual elements
  6. Facets (facet_*) - Small multiples
  7. Coordinates (coord_*) - Coordinate systems
  8. Labels (labs, ggtitle) - Text annotations

Part 4: Creating Your First Plot

Let’s build a plot step by step, understanding each component.

Step 1: Initialize the Plot

Code 
ggplot(pdat, aes(x = Date, y = Prepositions))

What happened?
- We created a plotting area
- We told ggplot which data to use (pdat)
- We defined the aesthetics: Date on x-axis, Prepositions on y-axis
- But no data appears yet! We need to add a geometry layer.

The aes() Function

aes() stands for aesthetics. It maps variables in your data to visual properties:

  • aes(x = Date) → Date values determine horizontal position
  • aes(y = Prepositions) → Preposition values determine vertical position
  • aes(color = Genre) → Genre determines color (we’ll add this later)

Think of aes() as the “instruction manual” telling ggplot how data maps to visuals.

Step 2: Add Points (Geometry Layer)

Code 
ggplot(pdat, aes(x = Date, y = Prepositions)) +  
  geom_point()

Now we see data! Each point represents one text.

Key insight: The + operator adds layers. Think of it like building with LEGO blocks.

Step 3: Add a Trend Line

Code 
ggplot(pdat, aes(x = Date, y = Prepositions)) +  
  geom_point() +  
  geom_smooth(se = FALSE) +  
  theme_bw()

What’s new?
- geom_smooth() adds a smoothed trend line (LOESS by default)
- se = FALSE removes the confidence interval shading
- theme_bw() applies a black-and-white theme

Layer Order Matters (Sometimes)

Layers are drawn in the order you add them:
- geom_point() then geom_smooth() → points underneath, line on top
- geom_smooth() then geom_point() → line underneath, points on top

Try reversing them to see the difference!

Step 4: Storing Plots as Objects

You can save plots to variables and modify them later:

Code 
# Store the base plot  
p <- ggplot(pdat, aes(x = Date, y = Prepositions)) +  
  geom_point() +  
  theme_bw()  
  
# Add nicer labels  
p + labs(x = "Year", y = "Frequency (per 1,000 words)")

Why is this useful?
- Create a base plot once
- Try different modifications without retyping everything
- Build complex plots incrementally
- Compare variations easily

Step 5: Plots in Pipelines

ggplot integrates beautifully with dplyr pipelines:

Code 
pdat |>  
  dplyr::select(DateRedux, GenreRedux, Prepositions) |>  
  dplyr::group_by(DateRedux, GenreRedux) |>  
  dplyr::summarise(Frequency = mean(Prepositions)) |>  
  ggplot(aes(x = DateRedux, y = Frequency,   
             group = GenreRedux, color = GenreRedux)) +  
  geom_line(size = 1.2) +  
  theme_bw() +  
  labs(title = "Mean Preposition Frequency Over Time",  
       x = "Time Period",  
       y = "Mean Frequency",  
       color = "Genre")

Pipeline Power:
1. Start with raw data
2. Select relevant variables
3. Calculate summaries
4. Pipe directly into ggplot
5. No intermediate objects needed!

When to Use Pipes

Use pipes when:
- You’re transforming data before plotting
- The transformation is specific to this one plot
- You want cleaner, more readable code

Don’t use pipes when:
- You need the transformed data elsewhere
- You want to inspect intermediate steps
- The transformation is very complex (better to break into steps)

Part 5: Customizing Axes and Titles

Professional plots need clear, informative labels and appropriate axis ranges.

Adding Titles and Labels

The labs() function handles all text labels:

Code 
p + labs(  
  x = "Year of Composition",  
  y = "Relative Frequency (per 1,000 words)",  
  title = "Preposition Use Over Time",  
  subtitle = "Based on the Penn Parsed Corpora (PPC)",  
  caption = "Source: Historical English texts, 1150-1913"  
)

Best practices for labels:
- X/Y axes: Always include units (e.g., “per 1,000 words”, “°C”, “%”)
- Title: Describes what the plot shows
- Subtitle: Adds context or methodology
- Caption: Data source, notes, or sample size

Challenge: Make your labels so clear that someone unfamiliar with your research could understand the plot immediately.

Controlling Axis Ranges

Use coord_cartesian() to zoom in/out without cutting data:

Code 
p + coord_cartesian(xlim = c(1000, 2000), ylim = c(0, 300))
coord_cartesian() vs scale_*_continuous()

Use coord_cartesian():
- Zooms without removing data
- Statistical computations use all data
- Preferred for most cases

Use scale_*_continuous(limits = ...):
- Actually removes data outside range
- Can affect statistical calculations
- Use when you truly want to exclude data

Styling Axis Text

Customize the appearance of axis labels and tick marks:

Code 
p + labs(x = "Year", y = "Frequency") +  
  theme(  
    axis.text.x = element_text(  
      face = "italic",    # italic, bold, plain  
      color = "red",   
      size = 10,   
      angle = 45,         # rotate labels  
      hjust = 1           # horizontal justification  
    ),  
    axis.text.y = element_text(  
      face = "bold",   
      color = "blue",   
      size = 12  
    )  
  )

Text properties you can control:
- face: “plain”, “italic”, “bold”, “bold.italic”
- color: Any R color
- size: Font size in points
- angle: Rotation in degrees
- hjust, vjust: Horizontal/vertical alignment (0-1)

Removing Axis Elements

Sometimes you want minimal axes:

Code 
p + theme(  
  axis.text.x = element_blank(),   # Remove x-axis labels  
  axis.text.y = element_blank(),   # Remove y-axis labels  
  axis.ticks = element_blank()     # Remove tick marks  
)

When to remove axes:
- Creating small multiples where shared axes apply
- Making minimalist graphics for presentations
- Focusing on overall patterns, not specific values

Custom Axis Breaks and Labels

Fine-tune where tick marks appear and what they say:

Code 
p +   
  scale_x_continuous(  
    name = "Year of Composition",  
    breaks = seq(1150, 1900, 50),    # Tick mark locations  
    labels = seq(1150, 1900, 50)     # Tick mark labels  
  ) +  
  scale_y_continuous(  
    name = "Relative Frequency",  
    breaks = seq(70, 190, 20),  
    labels = seq(70, 190, 20)  
  )
Custom Axis Labels

You can make labels say anything:

Code 
scale_x_continuous(  
  breaks = c(1200, 1500, 1800),  
  labels = c("Medieval", "Renaissance", "Modern")  
)

This is great for:
- Converting numbers to categories
- Abbreviating long labels
- Adding units to specific values

Part 6: Working with Colors

Color is one of the most powerful (and most misused) tools in data visualization.

Why Color Matters

Color can:
- ✅ Distinguish categories
- ✅ Show continuous values
- ✅ Highlight important data
- ✅ Create visual hierarchy
- ❌ Confuse if overused
- ❌ Exclude colorblind viewers if poorly chosen

Basic Color Mapping

Map color to a variable in aes():

Code 
ggplot(pdat, aes(x = Date, y = Prepositions, color = GenreRedux)) +  
  geom_point() +  
  theme_bw()

What happened?
- color = GenreRedux in aes() maps genre to color
- ggplot automatically picks colors
- A legend appears automatically

Inside vs. Outside aes()

Inside aes() - color represents DATA:

Code 
geom_point(aes(color = GenreRedux))  # Color varies by genre

Outside aes() - color is FIXED:

Code 
geom_point(color = "blue")  # All points blue

This is one of the most common ggplot mistakes!

Manual Color Selection

Choose your own colors with scale_color_manual():

Code 
ggplot(pdat, aes(x = Date, y = Prepositions, color = GenreRedux)) +  
  geom_point(size = 2) +  
  scale_color_manual(  
    name = "Text Genre",  # Legend title  
    values = c("red", "gray30", "blue", "orange", "gray80"),  
    breaks = c("Conversational", "Fiction", "Legal",   
               "NonFiction", "Religious")  
  ) +  
  theme_bw()

Useful R color names:
- Basic: “red”, “blue”, “green”, “yellow”, “orange”, “purple”
- Shades: “gray20”, “gray50”, “gray80” (0 = black, 100 = white)
- Fancy: “steelblue”, “coral”, “seagreen”, “salmon”

Continuous Color Scales

For continuous variables, use gradient colors:

Code

  scale_color_continuous() +  
  labs(color = "Preposition\nFrequency")

Better gradients:

Code 
p + geom_point(aes(color = Prepositions), size = 2) +  
  scale_color_viridis_c(option = "plasma") +  
  labs(color = "Preposition\nFrequency")

Color Brewer Palettes

Professional, colorblind-friendly palettes:

Code 
# See all available palettes  
display.brewer.all()

Using Brewer palettes:

Code 
p + geom_point(aes(color = GenreRedux)) +  
  scale_color_brewer(palette = "Set1") +  
  theme_bw()
Code 
p + geom_point(aes(color = GenreRedux)) +  
  scale_color_brewer(palette = "Dark2") +  
  theme_bw()
Choosing Color Palettes

For categorical data:
- “Set1”, “Set2”, “Set3” - Up to 8-12 distinct colors
- “Dark2”, “Paired” - Good contrast
- “Pastel1”, “Pastel2” - Softer colors

For sequential data (low to high):
- “Blues”, “Greens”, “Reds”
- “YlOrRd” (Yellow-Orange-Red)

For diverging data (negative to positive):
- “RdBu” (Red-Blue)
- “BrBG” (Brown-Blue-Green)
- “PiYG” (Pink-Yellow-Green)

Viridis: The Accessibility Champion

Viridis palettes are:
- Colorblind-friendly
- Print well in grayscale
- Perceptually uniform

Code 
p + geom_point(aes(color = GenreRedux), size = 2) +  
  scale_color_viridis_d() +  # _d for discrete  
  theme_bw()

Viridis options:

Code 
scale_color_viridis_d(option = "magma")    # Purple-yellow  
scale_color_viridis_d(option = "plasma")   # Purple-pink-yellow  
scale_color_viridis_d(option = "inferno")  # Black-purple-yellow

# Part 1: Understanding Data Visualization {#part1}  
  
## Principles of Good Visualization {#principles}  
  
Before we dive into code, let's establish some fundamental principles. **Good visualizations should:**  
  
### 1. **Be Clear and Informative**  
Every element should help the reader understand your data. This means:  
- Proper axis labels with units  
- Clear titles that explain what's being shown  
- Legends when multiple groups are displayed  
- Unambiguous visual elements  
  
### 2. **Accurately Represent Data**  
The visual representation must match the underlying data:  
- ❌ Don't use 3D effects that distort perception  
- ❌ Don't truncate bar chart axes (they must start at zero)  
- ✅ Do use appropriate scales  
- ✅ Do maintain proportional relationships  
  
### 3. **Match Dimensions**  
The number of visual dimensions should match the data dimensions:  
- 1 variable → 1-dimensional plot (bar chart, histogram)  
- 2 variables → 2-dimensional plot (scatter plot, line graph)  
- 3+ variables → use color, size, facets (not 3D!)  
  
### 4. **Use Appropriate Visual Encodings**  
Different data types need different encodings:  
  
| Data Type | Good Encoding | Poor Encoding |  
|-----------|---------------|---------------|  
| Categorical | Color, shape, position | Line (implies continuity) |  
| Continuous | Position, size, color gradient | Discrete shapes |  
| Ordered | Sequential colors | Random colors |  
| Time series | Line, position along x-axis | Unordered categories |  
  
### 5. **Be Intuitive**  
Your audience should understand the visualization without extensive explanation:  
- Follow conventions (time flows left to right)  
- Use familiar chart types when possible  
- Avoid misleading visual tricks  
- Include reference lines when helpful  
  
::: {.callout-warning}  
## Common Visualization Mistakes to Avoid  
  
**The "Lying with Statistics" Hall of Shame:**  
1. **Truncated axes** on bar charts (makes differences look bigger)  
2. **Cherry-picked scales** that hide or exaggerate trends  
3. **3D charts** that make values impossible to compare  
4. **Dual y-axes** that can be manipulated to show false correlations  
5. **Too many colors** that confuse rather than clarify  
6. **Pie charts with many slices** (almost always use a bar chart instead!)  
:::

# Part 2: The Three Frameworks {#frameworks}  
  
R offers three main approaches to creating visualizations. Understanding their philosophies helps you choose the right tool.  
  
## Base R: The Painter's Canvas {#base-r}  
  
**Philosophy:** Build plots like painting on a canvas—add elements one at a time.  
  
**Pros:**  
- No additional packages needed  
- Fine-grained control  
- Good for quick, simple plots  
  
**Cons:**  
- Verbose code for complex plots  
- Harder to maintain consistency  
- Limited automatic features (like legends)  
  
**When to use:** Quick exploratory plots, very simple visualizations  
  
```{r base_example, eval=FALSE}  
# Base R example (don't run - just for illustration)  
plot(pdat$Date, pdat$Prepositions)  
points(pdat$Date[pdat$Region == "North"],   
       pdat$Prepositions[pdat$Region == "North"],   
       col = "red")  
legend("topleft", legend = c("North", "South"),   
       col = c("red", "black"), pch = 1)  
```  
  
## Lattice: The Template Approach {#lattice}  
  
**Philosophy:** Use pre-designed templates that are easy to invoke but hard to customize.  
  
**Pros:**  
- Excellent for multi-panel plots  
- Very concise code  
- Good default aesthetics  
  
**Cons:**  
- Difficult to customize  
- Less flexible than ggplot  
- Smaller user community  
  
**When to use:** Quick multi-panel comparisons, academic work with simple plots  
  
```{r lattice_example, eval=FALSE}  
# Lattice example (don't run - just for illustration)  
library(lattice)  
xyplot(Prepositions ~ Date | GenreRedux, data = pdat)  
```  
  
## ggplot2: The Grammar of Graphics {#ggplot}  
  
**Philosophy:** Build plots like sentences—combine grammatical elements (data, aesthetics, geometries, scales).  
  
**Pros:**  
- Extremely flexible  
- Consistent, logical syntax  
- Beautiful defaults  
- Massive ecosystem of extensions  
- Active community  
  
**Cons:**  
- Requires learning the "grammar"  
- Can be verbose for very simple plots  
- Requires installing tidyverse  
  
**When to use:** Almost everything! Especially publication-quality figures and complex visualizations.  
  
::: {.callout-important}  
## Why We Focus on ggplot2  
  
This tutorial focuses exclusively on **ggplot2** because:  
  
1. It's become the industry standard in R  
2. The grammar approach is powerful and transferable  
3. Customization is straightforward once you understand the system  
4. It produces publication-ready graphics  
5. Extensive documentation and community support  
  
The "grammar of graphics" was developed by Leland Wilkinson and implemented in R by Hadley Wickham. It treats visualizations as composed of layers that can be combined systematically.  
:::  
  
## The ggplot2 Philosophy: Building in Layers  
  
Think of a ggplot as a **layered cake** where each layer adds information:  
  
```{r plot_layers, echo = F, message=F, warning=F}  
library(ggplot2)  
library(gridExtra)  
  
pdat <- base::readRDS("tutorials/introviz/data/pvd.rda", "rb")  
  
p1 <- ggplot(pdat) +  
  labs(title = "Layer 1: Initialize\nggplot(data)")  
  
p2 <- ggplot(pdat, aes(x = Date, y = Prepositions)) +  
  labs(title = "Layer 2: Map aesthetics\naes(x, y)")  
  
p3 <- ggplot(pdat, aes(x = Date, y = Prepositions)) +  
  geom_point() +  
  labs(title = "Layer 3: Add geometry\ngeom_point()")  
  
p4 <- ggplot(pdat, aes(x = Date, y = Prepositions)) +  
  geom_point() +  
  geom_smooth() +  
  labs(title = "Layer 4: Add layer\ngeom_smooth()")  
  
p5 <- ggplot(pdat, aes(x = Date, y = Prepositions)) +  
  geom_point() +  
  geom_smooth() +  
  theme_bw() +  
  labs(title = "Layer 5: Apply theme\ntheme_bw()")  
  
p6 <- ggplot(pdat, aes(x = Date, y = Prepositions)) +  
  geom_point(color = "gray20", alpha = .5) +  
  geom_smooth(color = "red", linetype = "dotted", size = .5) +  
  theme_bw() +  
  labs(title = "Layer 6: Customize\ncolors, alpha, etc.")  
  
grid.arrange(p1, p2, p3, p4, p5, p6, nrow = 2)  
```  
  
**The Building Blocks:**  
  
1. **Data** - What you're visualizing  
2. **Aesthetics** (`aes`) - What goes where (x, y, color, size, etc.)  
3. **Geometries** (`geom_*`) - How to display it (points, lines, bars)  
4. **Scales** (`scale_*`) - How aesthetics map to values  
5. **Themes** (`theme_*`) - Non-data visual elements  
6. **Facets** (`facet_*`) - Small multiples  
7. **Coordinates** (`coord_*`) - Coordinate systems  
8. **Labels** (`labs`, `ggtitle`) - Text annotations

# Part 4: Creating Your First Plot {#first-plot}

## Step 1: Initialize the Plot  
  
```{r plot1}  
ggplot(pdat, aes(x = Date, y = Prepositions))  
```  
  
**What happened?**  
- We created a plotting area  
- We told ggplot which data to use (`pdat`)

- **But no data appears yet!** We need to add a geometry layer.  
  
::: {.callout-important}  
## The `aes()` Function  
  
`aes()` stands for **aesthetics**. It maps variables in your data to visual properties:  
  
- `aes(x = Date)` → Date values determine horizontal position  
- `aes(y = Prepositions)` → Preposition values determine vertical position  
- `aes(color = Genre)` → Genre determines color (we'll add this later)  
  
Think of `aes()` as the "instruction manual" telling ggplot how data maps to visuals.  
:::

**Key insight:** The `+` operator adds layers. Think of it like building with LEGO blocks.

# Part 6: Working with Colors {#colors}  
  
Color is one of the most powerful (and most misused) tools in data visualization.  
  
## Why Color Matters  
  
Color can:  
- ✅ Distinguish categories  
- ✅ Show continuous values  
- ✅ Highlight important data  
- ✅ Create visual hierarchy  
- ❌ Confuse if overused  
- ❌ Exclude colorblind viewers if poorly chosen  
  
## Basic Color Mapping  
  
Map color to a variable in `aes()`:  
  
```{r colors1}  
ggplot(pdat, aes(x = Date, y = Prepositions, color = GenreRedux)) +  
  geom_point() +  
  theme_bw()  
```  
  
**What happened?**  
- `color = GenreRedux` in `aes()` maps genre to color  
- ggplot automatically picks colors  
- A legend appears automatically  
  
::: {.callout-important}  
## Inside vs. Outside `aes()`  
  
**Inside `aes()`** - color represents DATA:  
```{r aes_inside, eval=FALSE}  
geom_point(aes(color = GenreRedux))  # Color varies by genre  
```  
  
**Outside `aes()`** - color is FIXED:  
```{r aes_outside, eval=FALSE}  
geom_point(color = "blue")  # All points blue  
```  
  
This is one of the most common ggplot mistakes!  
:::  
  
## Manual Color Selection  
  
Choose your own colors with `scale_color_manual()`:  
  
```{r colors3}  
ggplot(pdat, aes(x = Date, y = Prepositions, color = GenreRedux)) +  
  geom_point(size = 2) +  
  scale_color_manual(  
    name = "Text Genre",  # Legend title  
    values = c("red", "gray30", "blue", "orange", "gray80"),  
    breaks = c("Conversational", "Fiction", "Legal",   
               "NonFiction", "Religious")  
  ) +  
  theme_bw()  
```  
  
**Useful R color names:**  
- Basic: "red", "blue", "green", "yellow", "orange", "purple"  
- Shades: "gray20", "gray50", "gray80" (0 = black, 100 = white)  
- Fancy: "steelblue", "coral", "seagreen", "salmon"  
  
[Full color reference →](http://www.stat.columbia.edu/~tzheng/files/Rcolor.pdf)

# Part 10: Themes and Styling {#themes}  
  
Themes control the non-data elements of your plot: backgrounds, grid lines, fonts, and more.  
  
## Built-in Themes  
  
ggplot2 includes several complete themes:  
  
```{r theme1}  
# Create base plot  
p <- ggplot(pdat, aes(x = Date, y = Prepositions)) +  
  geom_point(alpha = 0.5) +  
  labs(x = "", y = "")  
  
# Default theme  
p0 <- p + ggtitle("Default (theme_gray)")  
  
# Built-in alternatives  
p1 <- p + theme_bw() + ggtitle("theme_bw()")  
p2 <- p + theme_classic() + ggtitle("theme_classic()")  
p3 <- p + theme_minimal() + ggtitle("theme_minimal()")  
p4 <- p + theme_light() + ggtitle("theme_light()")  
p5 <- p + theme_dark() + ggtitle("theme_dark()")  
p6 <- p + theme_void() + ggtitle("theme_void()")  
p7 <- p + theme_linedraw() + ggtitle("theme_linedraw()")  
  
# Display all  
grid.arrange(p0, p1, p2, p3, p4, p5, p6, p7, ncol = 4)  
```  
  
**Theme characteristics:**  
  
| Theme | Background | Grid | Best For |  
|-------|-----------|------|----------|  
| `theme_gray()` | Gray | White | Default, general use |  
| `theme_bw()` | White | Gray | Publications, clean look |  
| `theme_classic()` | White | None | Traditional plots, no grid |  
| `theme_minimal()` | White | Minimal gray | Modern, clean |  
| `theme_light()` | White | Light gray | Easy on eyes |  
| `theme_dark()` | Dark | White | Presentations, dark mode |  
| `theme_void()` | None | None | Minimalist, art |  
  
::: {.callout-tip}  
## Choosing a Theme  
  
**For academic papers:** `theme_bw()` or `theme_classic()`  
**For presentations:** `theme_minimal()` or `theme_dark()` (dark background)  
**For web/reports:** `theme_minimal()` or `theme_light()`  
**For posters:** `theme_bw()` with increased base size  
**For artistic/abstract:** `theme_void()`  
:::

```{r reference_structure, eval=FALSE}  
  facet_FUNCTION(~VARIABLE) +  
  theme_STYLE() +  
  labs(title = "", x = "", y = "")  
```
